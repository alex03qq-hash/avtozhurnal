# АвтоЖурнал

Локальное веб-приложение для учёта расходов на автомобиль: заправки, ТО и ремонт, доходы,
поездки, склад запчастей и авто-досье для продажи машины.

Главная идея — **честная стоимость владения**. Приложение показывает не только «сколько я потратил
на бензин», а сколько реально стоит каждый километр с учётом ремонта, страховки, налогов, шин и мойки,
и заранее предупреждает о приближающемся ТО.

Сделано как офлайн-инструмент: все данные лежат в одном файле на вашем компьютере, интернет и аккаунты
не нужны, никакой аналитики и отправки данных наружу.

## Возможности

**Учёт**
- Несколько автомобилей с быстрым переключением в верхней панели.
- Заправки: дата, одометр, объём, цена за литр, сумма (считается автоматически), АЗС, признак «полный бак».
- Расходы по категориям: ТО, ремонт, запчасти, шины и шиномонтаж, страховка, налог, мойка, парковка, штрафы, прочее.
- Доходы (такси, доставка, аренда) и итоговая прибыль.
- Журнал поездок с себестоимостью и прибылью каждой поездки.
- Склад запчастей с артикулами (копирование артикула одной кнопкой) и датами установки.
- Интерактивный чек-лист перед выездом.

**Аналитика**
- Дашборд: расход л/100 км, стоимость километра, траты за месяц и за год, пробег, прибыль.
- Три графика на собственных SVG-компонентах: динамика расхода, траты по месяцам, структура расходов.
- Напоминания о ТО по пробегу и по дате одновременно, с порогами «скоро» и «просрочено».
- Прогноз износа деталей: процент израсходованного ресурса и остаток в километрах и днях.

**Данные и отчёты**
- Авто-досье: отчёт о машине (пробег, вложенные деньги, стоимость километра, история обслуживания,
  состояние по регламентам, запчасти, заправки) с печатью в PDF средствами браузера.
- Экспорт в CSV (с BOM и разделителем `;` — Excel открывает русский текст корректно).
- Полный бэкап в JSON и восстановление в режимах «заменить всё» или «добавить к текущим».
- Демонстрационные данные — два автомобиля и год истории, чтобы сразу увидеть, как всё работает.

**Интерфейс**
- Установка на телефон: приложение ставится на домашний экран, открывается без адресной строки,
  а ссылку на него телефон получает по QR-коду прямо со страницы «Настройки».
- Мобильная вёрстка: нижняя навигация, крупные элементы управления, таблицы превращаются в карточки.
- Работа без сети: оболочка приложения сохраняется в кэш, поэтому оно открывается, даже если
  компьютер с базой выключен (данные при этом, разумеется, недоступны — приложение честно об этом скажет).
- Светлая и тёмная темы (тема «как в системе» учитывает настройку ОС).
- Единицы измерения: километры и литры либо мили и галлоны (в базе данные всегда хранятся в км и литрах).
- Поддержка электромобилей: объём и расход считаются в кВт·ч.
- Полностью на русском языке, без внешних UI-библиотек и шрифтов.

## Требования

- **Node.js 18.18 или новее** (проверено на Node 22). Больше ничего устанавливать не нужно:
  нет нативных модулей, нет Docker, нет базы данных.
- Любой современный браузер (Chrome, Safari, Edge, Firefox).

## Быстрый старт

```bash
# 1. установка зависимостей
npm install

# 2. запуск в режиме разработки (API на :4000, интерфейс на :5173)
npm run dev
```

Откройте http://localhost:5173.

Чтобы сразу увидеть заполненный интерфейс, нажмите на пустом экране **«Загрузить демо-данные»**
или выполните `curl -X POST http://localhost:4000/api/demo`.

### Запуск «как в продакшене» одной командой

```bash
npm run build     # проверка типов + сборка интерфейса
npm start         # сервер на http://localhost:4000 раздаёт и API, и интерфейс
```

### Тесты

```bash
npm test          # 57 тестов: расчётное ядро, форматирование, хранилище, валидация
```

Дополнительно есть два смоук-теста «на живом приложении» (нужен запущенный сервер):

```bash
# проверка REST API: успешные сценарии, негативные случаи, устойчивость сервера
BASE_URL=http://localhost:4000 node scripts/api-smoke-test.mjs

# проверка интерфейса в реальном браузере через DevTools Protocol:
# заполняет формы, нажимает кнопки, проверяет сохранение после перезагрузки
BASE_URL=http://localhost:4000 node scripts/ui-smoke-test.mjs

# проверка готовности к установке на телефон: манифест, иконки, service worker, мобильная вёрстка
BASE_URL=http://localhost:4000 node scripts/pwa-check.mjs
```

## Переменные окружения

Скопируйте `.env.example` в `.env` (или экспортируйте переменные вручную). Секретов приложение не требует.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `4000` | Порт HTTP-сервера. В проде он же отдаёт собранный интерфейс |
| `DATA_DIR` | `./data` | Каталог с файлом базы `db.json` |
| `HOST` | `0.0.0.0` | Интерфейс прослушивания. `0.0.0.0` — доступно и с телефона в той же сети |
| `ACCESS_TOKEN` | — | Код доступа к журналу. Если задан, приложение требует его на телефоне (см. ниже) |
| `HTTPS_KEY` | — | Путь к ключу, если нужен https (см. «Установка на телефон») |
| `HTTPS_CERT` | — | Путь к сертификату для https |
| `NODE_ENV` | `development` | Режим работы (`production` — только информационно) |

## Резервные копии и перенос данных

- **Бэкап:** «Настройки» → «Скачать бэкап JSON» (или `GET /api/export/json`). Файл содержит все записи.
- **Восстановление:** «Настройки» → выберите режим («заменить все данные» или «добавить к текущим»)
  и укажите JSON-файл. Отчёт покажет, сколько записей добавлено.
- **Excel:** «Настройки» → кнопки экспорта CSV. Числа и русский текст открываются корректно.
- Вручную: база — это обычный файл `data/db.json`, его можно просто скопировать.
  При повреждении файла сервер сам сохранит его как `db.json.broken-<время>` и запустится с пустой базой.

## Авто-досье в PDF

Раздел «Авто-досье» → кнопка **«Печать / сохранить в PDF»**. В диалоге печати выберите
«Сохранить как PDF». На печать уходит только содержимое досье: панель управления, меню и кнопки скрыты
правилами `@media print`.

## Публикация в GitHub

```bash
GITHUB_TOKEN=ghp_ваш_токен node scripts/publish-to-github.mjs
```

Скрипт создаёт репозиторий `avtozhurnal` (публичный; `GITHUB_PRIVATE=true` — приватный)
и отправляет туда текущую ветку. Нужен персональный токен с правом `repo`
(или fine-grained: *Administration: Read and write* + *Contents: Read and write*).
Токен не сохраняется ни в файлах, ни в `.git/config`.

## Ограничения и что осталось за рамками

- **Нет GPS-трекинга.** Определение поездок по геолокации в браузере требует разрешений и постоянного
  доступа к позиции; в журнал поездки вносятся вручную.
- **Нет карты АЗС и краудсорсинговых цен.** Это требует внешнего сервиса и сетевых запросов,
  что противоречит офлайн-модели приложения.
- **Нет синхронизации между устройствами.** Данные живут в одном файле на компьютере; телефон
  работает как второй экран и требует, чтобы компьютер был включён.
- **Нет авторизации.** Кто угодно в вашей локальной сети может открыть журнал по адресу компьютера.
- **Нет push-уведомлений.** Напоминания видны в интерфейсе; уведомления на телефон не отправляются.
- **Авто-досье — печать средствами браузера.** Отдельный серверный генератор PDF не используется,
  чтобы не тащить в проект тяжёлые зависимости (Chromium/Puppeteer).
- **Одна валюта — российский рубль.** Пересчёт между валютами и смена символа валюты не предусмотрены.
- **Нет авторизации.** Приложение рассчитано на локальный запуск одним человеком.
